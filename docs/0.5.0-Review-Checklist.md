# AeroTrace 0.5.0 development review

Current operation and qualification status: [0.5.5 status](current-status.md). Older machine-specific results below are historical evidence; they do not describe current hardware presence or qualify later builds.


No new installer is supplied. The development executable is `out/build/desktop-release/apps/desktop/aerotrace_desktop.exe`; this computer must retain its Qt/Qwt and DDC development runtimes. F1 diagnostics and executable file properties identify version 0.5.0. The previous installed 0.4.0 copy is unchanged.

1. Open Welcome. Confirm your saved preferences/profile are retained and new replay sessions point to Documents → AeroSpace → Sessions. Existing recordings remain available in Sessions.
2. In Device setup, explicitly select Offline simulation for software rehearsal. For physical monitoring select DDC, Rescan DDC, verify driver/runtime evidence, and verify logical-to-physical assignments in the vendor Card Manager. Never treat simulated traffic as a hardware pass.
3. Start monitoring with an empty CSV folder or run name if desired. Confirm traffic records immediately. Edit those fields while monitoring; no ICD is required for raw recording.
4. In Live monitor choose Movable windows. Drag, resize, minimize/maximize, Tile and Cascade both channel windows inside the workspace. Filter one channel and confirm the other channel is unaffected. Select a record and Inspect it.
5. Switch to Tabs while recording. Check Both channels, External and Internal. Switch back; confirm capture and pane selections/filters remain intact. Restart the app after saving to check layout persistence.
6. Open Dashboard after capture has already run. Valid RT response lamps should still be green on the appropriate channel. Select an RT for response count, buses and last device time. Command-only traffic is not a terminal response; address 31 is broadcast.
7. Enter a CSV destination and a name such as `run1`. Stop & save must produce only `run1_int.csv` and `run1_ext.csv` there. Check the completion counts and compare against the recording. Full exports include traffic hidden by display filters.
8. If save fields are blank, check the Desktop, Documents and Browse shortcuts in the prompt. Cancel: monitoring stops, the finalized recording remains available, and no incomplete export is called successful. Retry from Live monitor or Sessions.
9. Open the saved session. Play/pause, step, change speed, seek near the end and back near the beginning. Check selected record identity/timestamps and replay dashboard observations.
10. Open F1 diagnostics and the operator guide. Preserve application journals and capture sidecars after any issue. UI delays, logging failures, SDK errors, buffer loss and export outcomes have distinct evidence.

Use `docs/SES-Bench-Checklist.md` for physical qualification with known passive traffic. Software checks cannot confirm a card, cable, bus coupling, independent clock synchronization, or electrical receive-only behavior.
